# SetterCheckerNew 项目计划

本文件只保留需求、模块职责、当前状态和待办。逐次调试、试验耗时和旧扫描流水不再追加；已提交的实现历史由 Git 保存。

## 一、目标与交付

读取 khengine 当前源码及必要依赖，判断函数是否修改数据，对照现有日志标签，输出差异报告。只对 `D:/KiHan/Packages/khengine` 提标签建议；`D:/KiHan` 只读。

- 修改数据的函数称为 Setter；不修改的称为 Getter。
- 真实行为与“最终是否记录日志”分别保存，不能混为同一个结论。
- 报告列出总函数数、检测数量与源码标签数量、两类标签差异、豁免复查、缺少原因的告警，以及当前不能判断的函数。
- 每项差异附带文件路径、函数位置、实际实现、修改了什么、为什么如此判断。缓存维护等是否值得豁免由业务复查说明，不按名称忽略。
- 输出文本、JSON 和标签修改预览；不自动修改游戏。

近期先交付一版能够扫描 khengine、明确展示已证明差异和未覆盖写法的工具，再与用户逐类讨论。阶段报告不是全部通过：不能判断的函数不伪装成 Getter 或 Setter，也不生成猜测补丁。

最终仍须完成当前材料可支持的托管分析、逐项复查差异，并实测性能。目标完整运行 5 秒以内，10 秒以内勉强可接受；验收耗时包含工具构建、源码上下文准备、缓存读取、分析和报告写出，另列各部分耗时。源码上下文仍有成本，但不再为分析生成游戏程序集。

## 二、判断规则

### 数据修改

- 修改已有对象、传入对象及其成员指向的对象、静态数据、数组、集合、事件或实际写入 `ref/out`，属于 Setter。仅有可写语法不代表实现真的写入。
- 被调用函数保存“修改当前对象／第几个参数／静态数据”等事实，再对应到调用者实际传入的对象。不能将被调用函数的 Setter 无条件复制给调用者。
- 创建 khengine 业务对象并返回、保存、注册或传给外部，属于 Setter；仅在内部创建和修改、没有传出的临时对象不算。
- 新容器可以指向旧对象；通过新容器修改旧对象仍算修改。复制结构体本身与修改其中引用指向的对象也须区分。
- 同一份材料、同一判断条件下，已有确定写入证据不反复证明；后面的独立未知调用不推翻已经发生的写入。但标签审计、返回对象及必要调用关系仍独立保留。
- 不把不同分支的对象和条件拼接成写入证据；函数内保留明确不可达代码和对象来源检查。按最新轻量方向，不再为每个入口推算整条调用链的运行状态或普遍要求证明前序调用正常返回；复杂执行条件无法由函数说明表达时单列，不恢复全局执行证明。
- Getter 必须证明所有相关行为都没有外部修改。未覆盖的循环、异常、对象来源或目标选择单列原因，不用保守猜测代替分析。

### 已确认的输入边界

- 采用 `Runtime/khengine.runtime.asmdef` 当前真实 Unity 编译参数，不额外枚举条件编译或其他平台组合。
- 普通入口假定其所属的完整构造类型已按约定初始化；不同泛型类型各自独立。不假设此前有人通过反射暗改运行库私有只读字段。
- 本次调用中真实可达的普通、反射或未知可写操作仍须检查，不能借入口约定忽略它们；共享静态数组也不会因为有初值而成为临时对象。
- 只有已证明的初始化值可以复用；复杂初始化、重入和异常关系尚不能证明时明确列出。此前其他入口准备过对象，不等于本入口进行了修改。
- 不使用 LogicData 限制合法输入。外部传入反射名称时，仍按现有材料中的类型、签名与合法成员范围处理。
- 源码直接由 Roslyn 读取函数操作；源码项目之间使用 CompilationReference，不生成内存或磁盘 DLL。真实托管 DLL 才读取 IL，两者产出同一种函数修改说明；参考程序集仍须映射到当前运行环境的真实实现。不能用旧 DLL 冒充当前源码。
- 不再索取缺失的原生材料，也不开发原生指令分析器。现有材料不能证明的原生影响单列；托管分析缺口不能借此忽略。
- 运行时生成新代码或加载材料范围外的程序集，明确说明超出范围，不猜其行为。

### 日志标签

- 方法级带原因、方法级不带原因、类级 `[NoLogTrack]` 都先相信其豁免；类级函数另记 `NLTClass`。
- 仍独立分析豁免函数的真实行为。仅裸标签且真实为 Setter 时告警“缺少 Reason”，并沿实际调用向上报告最短调用过程。
- 原因读取标签构造函数真正接收的原因字符串；仅有 `NoLogTrackFlag` 数值不算提供了原因。
- 带原因或类级豁免的 Setter 进入复查，不重复告警缺少原因。
- 豁免内部的写入不再让上层需要追踪；上层自己的写入、保存或返回业务对象仍单独判断。
- 标签不改变真实参数、字段写回、返回对象身份或能否正常返回；不能靠豁免改变程序本身的行为。
- `[LogTrack]` 只强制追踪，不改变真实行为。相互冲突的标签明确报错。
- 没有 NLT 或强制 LogTrack，且最终没有需要追踪的影响，才建议补 NLT；报告区分真实 Getter 与仅因下层豁免而不追踪的 Setter。
- 追踪决定未证明时不生成补丁；真实行为与标签生效后的判断共用原调用关系，不建立第二套图。

### 统计范围

纳入普通命名函数、运算符、类型转换、属性 setter、自定义事件 add/remove，以及类级豁免下的上述函数。

构造、析构、属性 getter、接口或抽象声明、无函数体的 extern、局部和匿名函数、编译器生成函数、`getInstance`、`BaseProxy_*` 只参与分析，不进入标签数量。按实际注入器规则，命名空间 `Tss`、`UnityEngine` 及后者子命名空间不提标签建议；不能扩大到 `Tss.Child`，也不取消类级豁免复查。

仅支持 Editor 的 khengine 程序集不进入标签统计，但仍可作为依赖材料；不按文件名中的 Editor、UI 等字样随意排除调用目标。

## 三、模块职责与当前评估

保留 Core、Cli、Tests。七个模块各一份主文件，加一份总入口；相关小类型留在模块内，不恢复一类一文件。

| 模块／现有文件 | 对应需求与保留内容 | 当前主要问题 |
| --- | --- | --- |
| 找材料／MaterialLoader.cs | 读取真实构建参数、源码和运行库；保留源码上下文及有效缓存，不生成游戏程序集 | 当前实现仍生成程序集，必须替换；保留真实输入与引用校验 |
| 函数总表／MethodCatalog.cs | 每个源码或 DLL 函数一个身份、一份说明；保存位置、参数、标签及实现列表 | 现有目录依赖生成的程序集，需改为源码符号与 DLL 声明共同登记 |
| 读函数内容／BehaviorReader.cs | 源码直接读操作，DLL 读指令；各自只提取一次事实，填写同一种说明 | 当前只有指令读取，需接入源码读取并复用已有 DLL 解码 |
| 找调用目标／CallTargetResolver.cs | 普通调用查函数表；接口、委托、反射查目标列表；只保存固定调用处和参数对应关系 | 当前 7,701 行；按调用路径复制环境及全局执行推算属于本轮替换对象 |
| 判断是否修改／EffectAnalyzer.cs | 在函数说明之间传递新增修改；按实际参数区分旧对象和内部新对象 | 当前以调用环境为工作单位，需改为函数说明，不重读函数体 |
| 对照标签／AnnotationEvaluator.cs | 应用可信豁免、生成缺原因告警和补标建议 | 职责较清楚，保留真实行为与追踪结果分离 |
| 写报告／ReportWriter.cs | 从同一结果生成数量、差异、证据、未覆盖项和修改预览 | 尚无最新完整 khengine 验收报告 |
| 总入口／SetterChecker.cs | 串起七步、统一并行数、取消与进度 | 保持薄入口，不扩成通用框架 |

函数体、声明及不变的索引应读取一次。调用点只对应接收对象、参数和目标，不能因调用者或入口不同复制函数。源码与 DLL 共用修改说明，不再为了共用底层指令强制源码生成 DLL。

## 四、工作方式与当前一轮

每个模块开工前先说明：解决哪个 khengine 问题、具体怎么改、复用哪些代码、删掉哪些重复、暂不覆盖哪些情况、怎样测试与计时。与用户讨论明确后才实施，不自动开始下一模块。

按用户最新要求，主 Agent 亲自编写、测试和审查，不再使用子 Agent。新增边界或需要改规则时先讨论，不无限扩大本轮任务。阶段反馈或等待用户确认可以结束当前回复，但不能称整个工具已完成。

### 当前方案：按函数保存说明，替换过重主干（方向已确认，实现未切换）

1. 保留七个模块和总入口，不新增框架。复用旧版源码操作读取与修改说明传播的思路，修正已知对象别名、循环和标签问题；保留新版真实材料定位、DLL 解码、标签规则和报告字段，不照搬旧版名称规则。
2. 材料模块建立当前源码上下文；源码引用源码，不生成程序集。外围为查全实现而保留声明和必要注册关系，不等于分析外围所有函数体。相关外围源码的解析成本仍要计时，不能宣称免费。
3. 每个函数保存一份修改说明：修改静态／当前对象／哪些参数及成员引用；返回对象来自哪里；字段写回和委托、反射目标；实际调用及参数对应关系；未覆盖原因和证据。用枚举、编号与集合表达，不保存父调用环境或展开后的调用路径。
4. 一次读取当前函数体，形成固定关系。接口、虚函数、委托和反射目标按真实声明或赋值登记，重复目标去重；字段引用用已登记的存储位置连接，不通过拼接越来越长的对象路径表示。
5. 修改说明有新增时只通知受影响调用者；相同事实不重复排队。Setter 结论不回退，但不能因此丢掉尚需向上层传递的参数修改信息。递归和互相调用在固定函数关系上传递，不复制调用环境。
6. 真实行为和标签生效后的追踪影响仍分开，使用同一份说明和调用关系。可信豁免不改变实际返回对象与字段写回；缺少原因的告警保留最短证据，不保存所有调用路径。
7. 不进行第二轮全量恢复、全项目重扫或全调用链执行证明。复杂写法仍无法表达时，记录具体函数和缺口，完成本轮报告后整体讨论，不边跑边补特例。

“一轮”的执行口径：一个分析请求、每个函数体一次事实提取、最后一次完整报告；新增说明可以在固定关系中传递，否则结果会取决于函数排列顺序。一次批次改动只运行一轮真实 khengine 验收，不以多次补扫拼成完成。验收记录不同函数数、事实提取次数、固定调用关系数、说明更新次数和总耗时。

## 五、性能、缓存与日志

- 接受 `-j4`、`-j 4`、`--jobs 4` 和任意正整数，默认 4；源码读取、函数事实提取和 DLL 读取共用一个上限，不写死四路、不再调度游戏程序集生成。
- 不同工作数 1／2／4／8 的结论、证据和排序必须一致。仅支持参数不代表已经取得实际加速；多线程不能掩盖重复计算。
- 保留会话源码上下文及有效持久化缓存；用实际源码、配置、引用、生成源码和分析规则核验，不凭日期或同名 DLL 复用。新主干不依赖历史生成的游戏程序集。
- 未保存文本可以覆盖当前编译清单中的文件；新增／删除／改名须更新真实清单。当前尚非完整编辑器接入，也没有持久化最终行为结论。
- 分析请求在排队前固定当前文本；取消后不复用未完成的函数事实或最终结论。
- 真实 khengine 的完整时间和报告是每次主干改动的验收门槛。当前批次只执行一次完整验收；分别列出源码准备、函数读取、说明传递及报告写出耗时，累计工作时间不重复加总。后续冷启动、复用与编辑后对比另行明确批次，不在本次失败后反复补跑。
- 源码程序集生成次数必须为零；函数体事实提取次数不超过实际分析的不同函数数；不因调用入口增多生成更多函数说明。不能用截断、超时或删除未覆盖项使结果表面达标。
- 文档只维护当前状态，不追加每次修复流水。运行日志已只保留阶段、工作量、耗时与错误；调用阶段最多每秒一条，结束时明确列出数量。原逐轮重算明细不再默认刷屏。

## 六、当前验证状态与验收要求

当前仍是旧重构主干：Release 全量测试 **1338/1338** 通过，Core **13,906** 个物理行；这些结果不证明本次轻量方案已经实现。新方向已写入规则，生产实现尚未切换。

七个模块已经串通，已有文本、JSON 与补丁预览出口；**最新完整 khengine 扫描与性能验收均未完成**。本轮实测约 11 分 21 秒后主动停止，材料阶段 17.1 秒，仍编译全部 144 个源码程序集。最后完整快照覆盖 15,068 个统计函数，3,197 个日志判断已证明、11,871 个待判断；停止前待处理调用仍增长到约 65 万。桌面 `SetterChecker本轮结果.md` 保留本次结果与抽查说明，不把部分报告称为验收通过。

主要缺口：完整动态候选仍扩大编译范围；相同函数的调用环境反复展开；部分循环、异常、初始化、反射返回和跨入口注册状态尚不能判断；编辑器自动同步未接入；真实多路加速未验收。

- 测试通过公开行为检查；同一种写法分别从源码和真实 DLL 输入，对照真实运行与预期。
- 每个模块从 khengine 找对应真实写法，在 Test 复刻；隔离了外部依赖的测试只能证明所保留部分，不能宣称整条业务链通过。
- 主 Agent 亲自对照本文件、编码规范、测试和真实项目审查，不再使用子 Agent。
- 可运行版本提交前检查完整差异、格式、编码、编译及全部测试，再提交并推送当前分支。只整理文档不代表发布新的分析版本。
- 最终报告逐项区分工具误判、应补标签、合理豁免及未覆盖问题；明确已证明修改但仍存在未分析原生调用的情况，不隐藏边界。
- 全部可验收项完成后才称项目完成；待用户确认下一模块或交付阶段报告不等同于最终验收通过。

## 七、实现约束

- 禁止业务函数或类名特例、猜测效果表、未知转 Getter／Setter、吞异常继续假报成功、缺文件扫描全盘、插件框架和空抽象。必要的材料身份、路径与输入完整性检查保留。
- 真实构建图决定源码身份；当前运行环境决定 DLL 身份及类型转交。不猜最新文件，不混用参考文件与运行实现；尚未使用的依赖不因此全量展开。
- Core 尽量不超过 13,000 行；本次不以历史 16,000 行例外作为继续增长的授权。若仍不能满足，先向用户说明原因，不得拆出 Core、挤行或删功能绕过限制。
- 遵循项目统一 C# 编码规范，每个函数有一行简短中文用途注释；公开函数另保留规范要求的 XML 文档。
- 文本统一 UTF-8 无 BOM，保留原换行；禁止新增或改写 SHA-256 实现及封装，可以使用已有实现。
- 不提交报告、缓存、生成目录、个人编辑器文件或 KiHan 文件。不建立无用途目录。
